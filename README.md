# AlgoHunter — an evolutionary attack lab for algorithms

**Find inputs that make sorting algorithms work unusually hard.** AlgoHunter is a Python genetic algorithm that evolves adversarial permutations, scores them using deterministic comparison counts, and compares performance against equal-budget random search. It includes a stand-alone, browser-based Python demo powered by **Pyodide / WebAssembly**.

**[Launch browser demo](https://ghassen258.github.io/algohunter/)** · [How evolution works](docs/ALGORITHM.md)

> This is an educational *optimization* project, not an LLM-powered product. It runs real Python in the browser. No paid AI APIs, remote server, or user data uploads required.

## Features

- Four instrumented sorting targets: Lomuto last-pivot quicksort, median-of-three quicksort, insertion sort, merge sort.
- Genetic algorithm: permutation-safe order crossover, three mutations, tournament selection, elitism.
- Equal-fitness-evaluation-budget random-search control, with honest negative as well as positive outcomes.
- Deterministic seeded experiments and per-generation history, including the winning input permutation.
- Browser demo: adjustable configuration, comparison chart, live generation updates and automatic slow-motion replay with Play/Pause, speed selection, and step-by-step genome visualization, cross-algorithm results, copy-array, downloadable JSON report.
- No Python runtime dependencies, no AI API keys; test suite using `unittest`.

## Run locally (Python 3.10+)

From the repository root:

```bash
python -m algohunter --algorithm quick_last --size 32 --population 40 --generations 35 --seed 42
```

Or install CLI command:

```bash
python -m pip install -e .
algohunter --algorithm insertion --size 24 --generations 30 --seed 7
```

Export a machine-readable experiment:

```bash
python -m algohunter --algorithm quick_median3 --size 24 --json > experiment.json
```

Supported algorithm names: `quick_last`, `quick_median3`, `insertion`, `merge`. Inputs are always unique integer permutations.

## Run the browser demo locally

The browser uses a Web Worker that loads Pyodide from a CDN, so **an internet connection is needed for the runtime to start**. Serve over HTTP rather than opening `file://` directly:

```bash
python scripts/build_site.py
python -m http.server 8000 --directory dist
```

Then open `http://localhost:8000`. The site loads a sample experiment immediately, then enables **Launch Evolution** once Python is ready. Search runs in a worker, not on the main UI thread. The actual Python engine is copied from `algohunter/core.py` into the site; there is no duplicate JS optimizer.

## Tests

```bash
python -m unittest discover -s tests -v
python scripts/build_site.py
```

GitHub Actions tests the Python engine and publishes the static web bundle to GitHub Pages. To enable the demo: repository **Settings → Pages → Build and deployment → Source → GitHub Actions**, then rerun the deployment workflow.

## Architecture

```text
algohunter/core.py     Instrumented sorting algorithms; GA and random-search baseline
algohunter/cli.py      JSON and readable command-line reports
algohunter/__main__.py Module entry point
web/index.html         Experiment dashboard
web/styles.css         Visual design
web/app.js             DOM, charts, progress, controls
web/worker.js          Pyodide and WebAssembly runtime
web/sample.json        Precomputed deterministic preview
scripts/build_site.py  Zero-dependency static site assembler
tests/test_core.py     Algorithm correctness, invariants, determinism, JSON bridge
```

### Why this is more than a sorting visualizer

The inputs are *generated by an optimizer*, rather than selected from a fixed list of known worst cases. The GA receives feedback from actual instrumented algorithms. The control experiment checks whether that learning beats simply trying more random inputs. On some configurations it doesn't, and the UI reports that explicitly.

### Limitations

- Educational comparison-count objective, not real elapsed execution time or actual CPU/energy performance.
- No arbitrary user-supplied code execution. Targets are curated instrumented sorting implementations.
- Genetic search is heuristic, not guaranteed to find an optimal global worst-case input.
- No persistent user accounts or server-side dataset: downloadable JSON only.
- Pyodide runtime downloads on first load; offline use requires self-hosting the runtime assets.

## Watch evolution in action

The first chart on page load is labeled **Sample experiment** (precomputed data). Wait until the Python engine shows **Ready**, choose an algorithm, and click **Launch Evolution** to run new searches locally. Although the underlying Python search may finish almost instantly, the interface automatically replays the recorded generations at a readable speed. Play/Pause, 0.5×/1×/2× speed, the slider, and arrow buttons let visitors inspect each generation. The graph grows as the replay advances; bars show the best-so-far input permutation, not a sorting animation.
